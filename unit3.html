一、本章定位与考情速览

Unit 3 Class Creation 是 APCSA 课程的"承上启下"章节：它承接 Unit 1（Java 基础类型与对象调用）与 Unit 2（控制结构），要求考生能够独立 设计一个完整类——选择恰当的实例变量、构造器、访问修饰符、存取方法，并在 FRQ 中写出可编译、可运行的实现代码。

  • 国际考 Q2 = Class Design 写完整类（2021 SingleTable / CombinedTable、2023 Sign、2024 Scoreboard、2025 SignedText，四年皆如此）。本题要求从需求文本直接写出 class 头、private 实例变量、带参数的 public 构造器、若干 public 存取方法/行为方法——这是本章最高频、最有把握拿分的大题。

  • MCQ 高频考点：访问修饰符（private/public）、static 与实例变量、方法签名、return 类型、final 修饰符、this 关键字、引用传递（String 与可变对象的差异）。

二、知识点与考点梳理（Topic 3.1–3.9）

板块 A：类设计基础（Topic 3.1 / 3.2）

Topic 3.1 Abstraction and Program Design（抽象与程序设计）

抽象的本质：把现实世界的事物（车、学生、玩家）抽象成 属性（attributes / state） 与 行为（behaviors / methods） 两个维度。这一步决定了后续怎么写实例变量和方法签名。

// 一辆 Car：属性 + 行为
public class Car {
    // 属性 (Topic 3.3 / 3.4)
    private double fuel;        // 当前油量（加仑）
    private double mpg;         // 每加仑英里数
    // 行为 (Topic 3.5)
    public Car(double fuel, double mpg) {
        this.fuel = fuel;
        this.mpg = mpg;
    }
    public boolean canMakeTrip(double miles) {
        return fuel * mpg >= miles;
    }
}

抽象的"四个步骤"：
1. 找出属性：从需求文本中找名词——"Car has fuel and mpg"。
2. 找出行为：从需求文本中找动词——"Car can make a trip"。
3. 决定可见性：实例变量一定 private；构造器和"会被外部调用"的方法一定 public。
4. 决定方法签名：包括返回类型（boolean / int / String / void）、参数列表（顺序和类型）、是否 static。

Topic 3.2 Impact of Program Design（程序设计的影响）

良好设计的三大收益（考试常以选择题形式出现）：
- 减少 IP / 抄袭争议（使用开放标准与文档良好的代码）；
- 提高系统可靠性（清晰的接口 + 单元测试）；
- 利于协作开发（明确的 access modifier 让其他类无需关心实现）。

课堂常见的对应原则：
- 信息隐藏（Information Hiding）：用 private 修饰所有实例变量，仅暴露必要的 public 方法。
- 接口稳定（Stable Interface）：方法签名只对外承诺"做什么"，不暴露"怎么做"。
- 数据抽象（Data Abstraction）：把"复杂数据结构"封装为简单接口，例如把 int[] numbers 封装为 ArrayList<Integer>。

考试提示：选择"程序设计带来的好处"的题目时，凡是出现"更好测试 / 更好维护 / 更少 IP 争议 / 更高可靠性"的选项，多半正确；如果选项声称"能完全避免 bug"或"无需注释"则是错误说法。

板块 B：Anatomy of a Class 与 Constructors（Topic 3.3 / 3.4）

Topic 3.3 Anatomy of a Class（类的解剖）

一个最小可用的 Java 类由三部分构成：

public class ClassName {            // ① 类头：决定类名与可见性
    private int field;              // ② 实例变量区（field section）
    public ClassName(int f) {       // ③ 构造器（与类同名；无返回值声明）
        field = f;
    }
    public int getField() {         // ④ 方法区（method section）
        return field;
    }
}

UML 类图（考试有时候会给出或要求识别）：

ClassName
- field : int
+ ClassName(f : int)
+ getField() : int

- 表示 private，+ 表示 public。UML 中仅列属性名与类型，不写 private int。

Topic 3.4 Constructors（构造器）

构造器是 与类同名、无返回类型声明、用于初始化实例变量 的特殊方法。考试最高频考点：

考点 描述 例子
带参数构造器 public ClassName(T1 p1, T2 p2) { ... } public Player(String name, int age)
默认构造器 类未声明任何构造器时 Java 自动提供，参数列表为空，所有实例变量取默认值（int=0 / double=0.0 / boolean=false / 引用=null） new Foo() 不报错
多构造器重载 参数列表不同（数量或类型不同）即可重载；返回类型不同不构成重载 同一类可有 Player() 与 Player(String, int)
防御性拷贝 可变对象作为参数时（如自定义 ArrayList），应用 new ArrayList<>(list) 复制一份 防止外部引用修改内部状态
this(...) 调用兄弟构造器 必须放在构造器第一行 this(); this("Bob");

示例：可变的构造器场景

public class Team {
    private String name;
    private ArrayList<String> members;
    public Team(String name, ArrayList<String> members) {
        this.name = name;
        this.members = new ArrayList<>(members);  // 防御性拷贝
    }
}

板块 C：Methods 与引用传递（Topic 3.5 / 3.6）

Topic 3.5 Methods: How to Write Them（方法的写法）

类别 签名模式 示例
访问器 (accessor / getter) public T getX() public int getScore() { return score; }
修改器 (mutator / setter) public void setX(T v) public void setScore(int s) { score = s; }
行为方法 (behavior) public T doSomething(...) public boolean canMakeTrip(double miles)
静态方法 public static T method(...) public static int add(int a, int b)

易错点：
- 方法的 return type 必须与 return 语句的表达式类型兼容（注意：return 缺失是编译错误）。
- void 方法体内允许 return; 但不能 return value;。
- 构造器不允许写返回值类型——public void ClassName() 不是构造器、是普通方法。
- 方法内可以调用同一类的 private 实例方法（隐式 this）。

Topic 3.6 Methods: Passing and Returning References of an Object（引用传递与返回）

考试中最重要的概念：对象引用作为参数时，传递的是引用的拷贝——方法内通过这个引用能修改原对象的内部状态，但不能让外部引用指向新对象。

String s = "Hello";           // 不可变
StringBuilder sb = new StringBuilder("Hi");  // 可变

mutate(s, sb);
System.out.println(s);   // 仍然是 "Hello"（不可变）
System.out.println(sb);  // 可能是 "Hi!!!"（被方法修改）

public static void mutate(String s, StringBuilder sb) {
    s = s + "world";        // 不会影响外部 s
    sb.append("!!!");       // 会修改外部 sb
}

关键规则：
- String 是不可变类型，所有修改（substring/concat/replace）都返回新对象，原对象不变。
- 自定义类、StringBuilder、ArrayList 是可变类型。
- 方法不能访问参数对象的 private 字段，除非参数所属类与当前类相同（同包或同顶层类）。

返回引用的语义：

public StringBuilder getName() {
    return new StringBuilder("Default");  // 返回的是这个新对象的引用
}

调用者拿到引用后，对返回对象的修改会影响该返回对象（因为它就是返回的那个对象）。

板块 D：Static 与 Scope（Topic 3.7 / 3.8）

Topic 3.7 Class Variables and Methods（static 变量与方法）

static 修饰的成员属于 类本身，而非类的某个实例：

类型 访问方式 数量
实例变量 obj.field（每个对象各自一份） 每个对象一份
static 变量（类变量） ClassName.field（所有对象共享一份） 全类一份 
public class Widget {
    private int number;            // 实例变量：每个 Widget 各一份
    private static String word = "start";  // 静态变量：所有 Widget 共享
    public static void updateWord(String s) {  // 静态方法
        word = s;
    }
}

static 方法的限制：
- 不能直接访问实例变量 / 实例方法（除非传入对象引用）。
- 不能使用 this 关键字（因为 this 指向某个实例，而 static 属于类）。
- 通常作为工具方法或计数器/全局状态使用（但考试中尽可能避免全局状态）。

Topic 3.8 Scope and Access（作用域与访问）

变量可见性从里到外的优先级（就近遮蔽）：

1. 块级局部变量 (最优先) → 2. 方法参数 → 3. 实例变量 → 4. 静态变量 (最外)

public class Student {
    private String name = "Bob";

    public void setName(String name) {
        name = name;        // ❌ 错误：两边都是参数，实例变量未被赋值
        this.name = name;   // ✅ 正确：用 this.name 区分实例变量
    }
}

访问修饰符总结（Unit 3 范围内）：

修饰符 同类 同包 子类 其他包
private ✅ ❌ ❌ ❌
(default/package) ✅ ✅ ❌ ❌
public ✅ ✅ ✅ ✅

Unit 3 不考 protected 和包级细节，但 private 与 public 必须能区分。

板块 E：this Keyword（Topic 3.9）

Topic 3.9 this Keyword（this 关键字）

this 是一个隐式参数，代表"当前对象"本身。两个核心用法：

用法 1：区分参数与实例变量同名

public class Rectangle {
    private double width;       // 实例变量
    private double height;
    public Rectangle(double width, double height) {
        this.width = width;     // 左 this.width 是实例变量，右侧是参数
        this.height = height;
    }
}

用法 2：用 this(...) 调用同类的另一个构造器（须放在构造器第一行）

public Player() {
    this("Anonymous", 0);     // 必须放在第一行
}
public Player(String name, int score) {
    this.name = name;
    this.score = score;
}

易错点：
- static 方法内 不能使用 this（因为没有"当前对象"）。
- 静态变量被实例变量遮蔽时不能用 this.staticField（应使用 ClassName.staticField）。

考试提示：MCQ 出现构造器体内部"左边写 x = x;"几乎一定是错误的，正确写法是 this.x = x;。

三、本章重难点与易错点清单（按出错频率排序）

高频易错点 TOP 10

  1. 构造器写错返回值类型：public void Player(int s) 是普通方法不是构造器，类外部 new Player(...) 会编译失败。
  2. 混淆实例变量与类变量：static int count = 0; count++; 是所有对象共享；非 static 是每个对象各自一份。
  3. this 与 static 误用：在静态方法内写 this.field 是编译错误。
  4. 访问修饰符混淆：public int score 让外部能直接改写实例变量，违反"实例变量永远 private"的最佳实践——MCQ 几乎每年必考。
  5. return 语句缺失：声明 public int getScore() 但方法体内忘了 return 会编译失败。
  6. return 类型与方法签名不一致：public double getScore() 写成 return score;（score 是 int）虽然 Java 会自动提升，但 public int getScore() 写 return "abc"; 会编译错误。
  7. String 与 StringBuilder 混淆：把 s = s + "x" 误以为能修改原 s；StringBuilder sb.append("x") 才是修改。
  8. 无参数构造器消失：一旦定义了带参数的构造器，Java 不再自动提供无参数构造器，new Foo() 失败。
  9. 方法重载只看返回类型：仅返回类型不同不是有效的重载（编译错误：duplicate method）。
  10. this(...) 放错位置：this(...) 必须放在构造器第一行，否则编译失败。

学习建议

  • 学会画类图：遇到 FRQ 时，先画出 UML 类图（属性 + 方法），再开始写代码——能极大减少漏写字段的概率。
  • 区分 static 与非 static：判断"是否需要每个对象一份"——static 用于"类级别共享"，例如计数器、全局配置；非 static 用于"对象级别独立状态"。
  • 构造器与 setter 关系：如果构造器已完整初始化所有字段，则不必立即写 setter；只有"对象创建后还能修改"的字段才需要 setter。
  • 优先使用 this.field：构造器内对实例变量赋值一律用 this.field = param;，避免遮蔽。

四、MCQ 真题精选与详解

本章 8 道 MCQ 全部来自 AP Classroom 官方 Unit 3 Class Creation 题库（New Unit 3 TopicQuestion MCQ + MCQ Part A + MCQ Part B），题面使用原版英文题干 + 中文详解。

MCQ-1（TopicQuestion #1：实例变量与构造器的可见性）

Consider the design of a Player class that will contain two int attributes and a constructor. The class will also contain a method getScore that can be accessed from outside the class. A partial definition of the Player class is shown.

public class Player
{
    /* missing code */
}

Which of the following replacements for /* missing code */ is the most appropriate implementation of the class?

(A)

private int score;
private int id;
public Player(int playerScore, int playerID) { /* implementation not shown */ }
private int getScore() { /* implementation not shown */ }

(B)

private int score;
private int id;
public Player(int playerScore, int playerID) { /* implementation not shown */ }
public int getScore() { /* implementation not shown */ }

(C)

public int score;
public int id;
public Player(int playerScore, int playerID) { /* implementation not shown */ }
private int getScore() { /* implementation not shown */ }

(D)

public int score;
public int id;
public Player(int playerScore, int playerID) { /* implementation not shown */ }
public int getScore() { /* implementation not shown */ }

答案：B

详解：实例变量一定要 private（信息隐藏），构造器必须 public（外部需要 new Player(...)），getScore 因为要"被外部访问"，必须是 public。

MCQ-6（MCQ Part B #4：String 不可变性 + 参数传递）

详解：

Part C · 参考解法（Java）

public class CombinedTable
{
    private SingleTable t1;
    private SingleTable t2;

    public CombinedTable(SingleTable t1, SingleTable t2)
    {
        this.t1 = t1;
        this.t2 = t2;
    }

    /** Returns true if the given number of customers can be seated
     *  at this combined table. */
    public boolean canSeat(int numCustomers)
    {
        return numCustomers <= t1.getNumSeats() + t2.getNumSeats() - 2;
    }

    /** Returns the desirability of this combined table. */
    public double getDesirability()
    {
        double avg = (t1.getViewQuality() + t2.getViewQuality()) / 2;
        if (t1.getHeight() == t2.getHeight())
        {
            return avg;
        }
        return avg - 10;
    }
}

Part D · 评分要点

  • 正确声明 private SingleTable t1, t2; 两个实例变量；
  • 构造器 public CombinedTable(SingleTable, SingleTable) 用 this.t1/t2 接收参数；
  • canSeat(int) 返回 numCustomers ≤ t1.getNumSeats() + t2.getNumSeats() - 2；
  • getDesirability() 中先计算 avg = (v1 + v2) / 2，再用 if (t1.getHeight() == t2.getHeight()) 区分两种情况；
  • 等高时返回 avg；不等高时返回 avg - 10（常见错误：写成 Math.min(...)）；
  • t2.setViewQuality(80) 后 c2.getDesirability() 变化，体现「共享引用语义」（不存副本）；
  • 整个类要求无 static 修饰（因为依赖具体对象）。

Part C · 参考解法（Java）

public class Sign
{
    private String message;
    private int width;

    public Sign(String message, int width)
    {
        this.message = message;
        this.width = width;
    }

    public int numberOfLines()
    {
        return (message.length() + width - 1) / width;
    }

    public String getLines()
    {
        String result = "";
        for (int i = 0; i < numberOfLines(); i++)
        {
            int start = i * width;
            int end = Math.min(start + width, message.length());
            result += message.substring(start, end);
            if (i < numberOfLines() - 1)
            {
                result += ";";
            }
        }
        return result;
    }
}

Part D · 评分要点

  • 正确声明实例变量与构造器；
  • numberOfLines() 使用上取整公式或等价的 if (len % w == 0) return len/w; else return len/w+1;；
  • getLines() 中循环次数等于 numberOfLines()；
  • substring(start, end) 的 end 用 Math.min(...) 防止越界；
  • 行间分隔符为 ;。

info = game.getScore(); "1-8-Red"

Write the complete Scoreboard class. Your implementation must meet all specifications and conform to the examples shown in the preceding table.

Part B · 中文思路与考点

  • 状态：四个实例变量：team1Name, team2Name, score1, score2, active（active 可用 boolean isTeam1Active 或 int active 1/2 表示）。
  • 构造器：初始化得分为 0，记录双方名字，设置"active team = team 1"。
  • recordPlay(int points)：
  • 如果 points > 0：增加 active 队伍的分数；
  • 否则（points == 0）：切换 active；
  • 参数 points 已经题目保证"非负整数"，不需要再校验负数。
  • getScore()：返回 "score1-score2-activeName"。

考点：Topic 3.3 / 3.4、Topic 3.5 方法、Topic 2.3 if / Topic 2.4 nested if 控制结构。

Part C · 参考解法（Java）

public class Scoreboard
{
    private String team1Name;
    private String team2Name;
    private int score1;
    private int score2;
    private boolean isTeam1Active;

    public Scoreboard(String name1, String name2)
    {
        team1Name = name1;
        team2Name = name2;
        score1 = 0;
        score2 = 0;
        isTeam1Active = true;
    }

    public void recordPlay(int points)
    {
        if (points > 0)
        {
            if (isTeam1Active)
            {
                score1 += points;
            }
            else
            {
                score2 += points;
            }
        }
        else  // points == 0
        {
            isTeam1Active = !isTeam1Active;
        }
    }

    public String getScore()
    {
        String activeName = isTeam1Active ? team1Name : team2Name;
        return score1 + "-" + score2 + "-" + activeName;
    }
}

Part D · 评分要点

  • 4-5 个正确的 private 实例变量；
  • 构造器初始化得分为 0 且 isTeam1Active = true；
  • recordPlay(int points) 分两个分支：points > 0 更新得分；points == 0 切换 active；
  • getScore() 返回 "score1-score2-activeName" 格式；
  • 不调用 recordPlay 之外的方法。

Part A · Official English Wording (from College Board 2025 FRQ #2)

This question involves the SignedText class, which contains methods that are used to include a signature as part of a string of text. You will write the complete SignedText class, which contains a constructor and two methods.

The SignedText constructor takes two String parameters. The first parameter is a first name and the second parameter is a last name. The length of the second parameter is always greater than or equal to 1.

The getSignature method takes no parameters and returns a formatted signature string constructed from the first and last names according to the following rules:
- If the first name is an empty string, the returned signature string contains just the last name.
- If the first name is not an empty string, the returned signature string is the first letter of the first name, a dash "-", and the last name, in that order.

The addSignature method returns a possibly revised copy of its String parameter. The parameter will contain at most one occurrence of the object's signature, at either the beginning or the end of the parameter. The returned string is created from the parameter according to the following rules:
- If the object's signature does not occur in the String parameter, the returned String is the value of the parameter with the signature added to the end.
- If the object's signature occurs at the end of the String parameter, the returned String is the unchanged value of the parameter.
- If the object's signature occurs at the beginning of the String parameter, the returned String is the value of the original parameter with the signature removed from the beginning and appended to the end of the parameter.

Part B · 中文思路与考点

  • 状态：private String firstName; private String lastName;
  • getSignature()：判 firstName.length() == 0，分别返回 lastName 与 firstName.substring(0,1) + "-" + lastName。
  • addSignature(String text)：
  • 用 text.endsWith(signature) 判末尾：直接返回 text；
  • 用 text.startsWith(signature) 判开头：返回 text.substring(signature.length()) + signature；
  • 否则返回 text + signature。

考点：Topic 3.5 方法 + Topic 1.15 / Topic 2.10 String 方法（substring/startsWith/endsWith）。

Part C · 参考解法（Java）

public class SignedText
{
    private String firstName;
    private String lastName;

    public SignedText(String firstName, String lastName)
    {
        this.firstName = firstName;
        this.lastName = lastName;
    }

    public String getSignature()
    {
        if (firstName.length() == 0)
        {
            return lastName;
        }
        return firstName.substring(0, 1) + "-" + lastName;
    }

    public String addSignature(String text)
    {
        String sig = getSignature();
        if (text.endsWith(sig))
        {
            return text;
        }
        if (text.startsWith(sig))
        {
            return text.substring(sig.length()) + sig;
        }
        return text + sig;
    }
}

Part D · 评分要点

  • 构造器使用 this.firstName / this.lastName 接收参数；
  • getSignature() 用 firstName.length() == 0 分支返回 lastName 或 firstName.substring(0,1) + "-" + lastName；
  • addSignature 三分支：endsWith 不动 / startsWith 移动 / 否则追加；
  • 三个字符串操作都正确使用 startsWith / endsWith / substring。

六、应试技巧清单

MCQ 限时训练策略（建议节奏）

  • 每题 ≤ 75 秒：FRQ 占用约 35 分钟/道的总时间下，MCQ 需保持 75 秒/题的稳定节奏。
  • 先做"明确送分"：看到 static / private / public / this 即可直接判断的题，先做——这能在 5-10 秒内拿到分。
  • "代码追踪"题放最后：涉及复杂方法调用的题耗时较多（特别涉及 String 拼接和 static 共享变量变化），可以先标记留待最后 5 分钟单独冲刺。

FRQ 写作策略

  • 先画类图：在草稿纸上画出 UML 类图（属性 + 方法签名 + 构造器），再开始写代码——这能减少漏字段。
  • 先实现构造器：构造器是核心，先写 this.field = param; 模式把所有字段都初始化。
  • 再实现行为方法：行为方法通常调用构造器已初始化的字段，逻辑简单。
  • 最后处理返回字符串：用 + 拼接即可，注意 "" 与 null 的边界。

代码追踪（Tracing）口诀

  • 三步法：① 标出每个变量初始值；② 按方法调用顺序一行一行执行；③ 输出/返回值核对。
  • static 单独追踪：static 字段所有对象共享，只跟踪一份。
  • 方法参数 = 局部变量：进入方法后第一件事是把参数抄到草稿纸左边。

易错点自检清单

  • [ ] 实例变量是否全部 private？构造器是否 public？
  • [ ] 方法签名里的返回类型与 return 值是否兼容？
  • [ ] void 方法体内有没有出现 return value;？
  • [ ] String 修改是赋值给原变量还是返回了新对象？
  • [ ] static 方法内有没有访问非 static 字段？
  • [ ] 构造器有没有写返回值类型（public void ClassName(...) 不是构造器）？
  • [ ] this(...) 是否放在了构造器第一行？
  • [ ] final 字段是否在每个构造器内都被赋值？

七、章节总结

本章 Unit 3 Class Creation 是 APCSA 课程中最考验"代码工程能力"的章节：从 Unit 1 / Unit 2 调用既有类（如 String、ArrayList、Math）到本章亲手设计一个类，是 Java OOP 入门的关键一步。本章考察的核心能力包括：

  1. 根据需求文本设计类：识别属性（private 实例变量）、行为（public 方法）、构造器（public，参数对应属性）。
  2. 正确使用访问修饰符：实例变量总是 private，方法与构造器按"是否需要外部调用"决定 public/private。
  3. 掌握 static 与实例变量的区别：所有对象共享 vs 每个对象独立。
  4. 理解引用语义：String 不可变 / StringBuilder 可变；对象引用作为参数时，方法内能修改对象内部状态但不能让引用指向新对象。
  5. 使用 this 关键字：解决参数与字段同名遮蔽；用 this(...) 调用兄弟构造器。
  6. 设计跨方法的一致行为：如 Scoreboard 中 recordPlay 改变 active 状态后 getScore 能正确读出新 active。

掌握本章后，下一章 Unit 4 Data Collections 将进一步使用 Array、ArrayList、2D Array 三类容器——这些容器在 FRQ 中常常是 Q3 / Q4，而本章学到的类设计思想同样适用于"容器 + 元素"的设计。
