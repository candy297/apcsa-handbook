一、本章定位与考情速览

本章是 APCSA 课程的开篇章节，对应官方大纲 Unit 1：Using Objects and Methods。内容覆盖 Java 程序的基本语法元素、表达式求值、方法的定义与调用、Math 类常用方法以及 String 类的核心 API。本章虽不涉及复杂的控制流与数据集合，但所学的"对象-方法-调用"思维模型贯穿全场考试，是后续 Unit 2（Selection and Iteration）、Unit 3（Class Creation）与 Unit 4（Data Collections）的基础。

1.1 新大纲四大单元与考试权重

2025 年秋起，APCSA 课程框架由旧的 10 个单元重组为 4 个单元，与本课程四个章节一一对应。选择题（MCQ）部分各单元权重如下：

单元（本课程章节）MCQ 权重建议课时
Unit 1：Using Objects and Methods（第一章）15–25%约 32–34 课时
Unit 2：Selection and Iteration（第二章）25–35%约 29–31 课时
Unit 3：Class Creation（第三章）10–18%约 20–22 课时
Unit 4：Data Collections（第四章）30–40%约 50–52 课时

1.2 考试结构

考试整体由 Section I（MCQ）与 Section II（FRQ）两部分组成，时长各 90 分钟，分值占比与题量如下表所示。

1.3 本章与 FRQ 的关联（备考重点提示）

根据新版考纲，FRQ 第 1 题（Methods and Control Structures）分为两部分：

  • Part A（4 分）：要求编写含条件或循环的方法，并调用题目所给类的方法；
  • Part B（3 分）：明确要求调用 String 类的方法。

也就是说，第一章的 String 方法（length、substring、indexOf 等）是 FRQ 的高频考点，必须达到"闭卷熟练"的程度。2021 年国际考 FRQ1（WordMatch）的 scoreGuess / findBetterGuess 就是综合运用 String 方法的典型（见本手册第四节 FRQ-5）。

格式说明

2021–2025 年国际考采用旧版 9 分制 FRQ1（part (a) + part (b) 合计 9 分）；2026 年起改为新版 7 分制（Part A 4 分 + Part B 3 分）。以下真题按年份倒序排列，每题均给出完整题面、官方参考解答与评分要点。

此外，MCQ 中所有单元的题目都会大量阅读代码，第一章培养的代码追踪（tracing）能力是全场考试的基础。

二、知识点与考点梳理（Topic 1.1–1.15）

本章共 15 个 Topic，按知识结构分为五大板块。每个知识点均标注考纲 Learning Objective（LO）编号，便于对照官方大纲复习。LO 编号格式为"单元号.Topic号.知识点小标号"，例如 LO 1.1.A 表示 Unit 1、Topic 1.1 的第 A 小点。

板块 A：Java 程序基础（Topic 1.1–1.2）

本板块聚焦程序设计的最基础概念：算法的描述方式、编译与执行流程、三类常见错误的区分，以及变量与三种基本数据类型的声明与使用。Topic 1.1–1.2 是整门课程的认知起点，MCQ 每年固定考查 1–2 道"哪种错误类型""哪种类型声明"的概念辨析题。

A1. 算法、编程与编译器（Topic 1.1，LO 1.1.A–1.1.C）

核心概念：

  • 算法（algorithm）：完成任务或解决问题的逐步过程，可以用自然语言或图示表示（LO 1.1.A）。
  • 顺序执行（sequencing）：过程中的步骤按顺序、一次一步地完成。
  • 编译与执行：代码可在任何文本编辑器中编写；IDE 集成了编写、编译、运行工具。编译器会检查部分错误，编译器能发现的错误必须修复后程序才能运行（LO 1.1.B）。
  • 三类错误 + 异常（LO 1.1.C，概念题高频考点）：
错误类型英文发现时机特征
语法错误syntax error编译期违反语言规则，编译器报错
逻辑错误logic error测试期程序能运行但结果不符合预期
运行时错误run-time error运行期通常导致程序异常终止
异常exception运行期一类运行时错误，中断程序正常执行流程

记忆口诀：编译器抓语法，测试抓逻辑，运行抓异常。判断"哪种错误"是 MCQ 常见的概念题。

A2. 变量与数据类型（Topic 1.2，LO 1.2.A–1.2.B）

核心概念：

  • 数据类型（data type） = 一组值 + 这组值上的操作。类型分为基本类型（primitive）和引用类型（reference）两大类（LO 1.2.A）。
  • 本课程只考三种基本类型（LO 1.2.B.1）：int（整数）、double（实数）、boolean（true/false）。
  • 考纲排除项：long、short、byte、float、char 不在考试范围内。
  • 变量是存储位置，有名字和类型；基本类型变量直接存值。
int age = 16;          // 整数
double gpa = 3.85;     // 实数
boolean isPass = true; // 布尔值

选择题考法：给一个场景（如"存储精确到 0.1 度的体温"），选出正确的类型声明——精确到小数必须用 double，用 int 会丢失精度。

板块 B：表达式与运算（Topic 1.3–1.6）

本板块是 MCQ 中输出值类题目的"重灾区"，每年固定考查 3–4 道。重点是理解 Java 的混合运算规则（两个 int 运算仍为 int）、整数除法的截断、复合赋值运算符与自增运算符的语义，以及强制类型转换的"截断而非四舍五入"特性。整除、cast 位置、运算优先级三者的组合是常见陷阱。

B1. 输出与字符串字面量（Topic 1.3，LO 1.3.A–1.3.B）

  • System.out.print 输出后不换行；System.out.println 输出后换行（LO 1.3.A.1）。
  • 字面量（literal）：代码中固定值的表示。字符串字面量必须用双引号括起；未加引号的 hello 是变量名而非字符串，会引发编译错误。
  • 转义序列：\"（双引号）、\\（反斜杠）、\n（换行）——考试要求掌握这三种（LO 1.3.B.3）。
System.out.print("cat ");
System.out.println("dog ");
System.out.println("horse ");
System.out.print("cow ");
// 输出：
// cat dog
// horse
// cow

B2. 算术表达式（Topic 1.3，LO 1.3.C）

  • 运算符：+、-、*、/、%（LO 1.3.C.2）。
  • 混合运算规则（本章第一高频考点）：
    • 两个 int 运算 → 结果仍是 int；
    • 至少一个 double 参与运算 → 结果为 double。
  • 整数除法：两个 int 相除只保留商的整数部分，如 5 / 2 得 2，不是 2.5（LO 1.3.C.3）。
  • 取余 %：a % b 是 a 除以 b 的余数。考纲只需掌握 a ≥ 0、b > 0 的情况（LO 1.3.C.4）。
  • 运算优先级（LO 1.3.C.5）：*、/、% 高于 +、-；同级从左到右；括号可改变优先级。
  • 整数除以 0 → ArithmeticException（LO 1.3.C.6）。double 参与的除零不在考试范围内。
System.out.println(7 / 2);        // 3   （int / int = int，截断）
System.out.println(7.0 / 2);      // 3.5 （有 double 参与）
System.out.println(7 % 3);        // 1
System.out.println(1 + 2 * 3 % 4); // 3  （先 2*3=6，再 6%4=2，再 1+2）

B3. 赋值语句与输入（Topic 1.4，LO 1.4.A–1.4.B）

本节重点是赋值与输入的边界：变量必须先声明再赋值；引用类型可赋值为 null；Scanner 是获取输入的一种方式，但"具体怎么读"不考。

  • 变量必须先赋值才能使用；引用类型可赋值为对象或 null（LO 1.4.A.1）。
  • = 是赋值：把右边表达式的值存入左边变量；右边先求值（LO 1.4.A.2）。
  • 表达式求值产生单一值，且该值有类型（LO 1.4.A.3）。
  • Scanner 类是获取键盘文本输入的一种方式；具体的输入方式不在考试范围内（LO 1.4.B）。
  • 考纲排除项：a = b = 4; 这类"表达式内赋值"不考。

B4. 强制类型转换与数值范围（Topic 1.5，LO 1.5.A–1.5.C）

本节是 MCQ 中输出值类题目的另一高频来源。核心是 cast 的"截断"语义以及"四舍五入"必须靠手动加 0.5 实现的考点。

  • (int) 和 (double) 转换符可实现类型转换（LO 1.5.A.1）。
  • double 强转 int 是截断（truncate），不是四舍五入：直接丢掉小数点右侧数字（LO 1.5.A.2）。
  • int 会自动拓宽（widening）为 double（LO 1.5.A.3），如 double x = 3; 合法。
  • 四舍五入技巧（考纲明确要求）（LO 1.5.A.4）：
    • 非负数：(int)(x + 0.5)
    • 负数：(int)(x - 0.5)
  • int 用 4 字节存储，范围是 Integer.MIN_VALUE（约 -21.47 亿）到 Integer.MAX_VALUE（约 21.47 亿）；超出范围发生整数溢出（overflow），结果仍在 int 范围内但不是期望值（LO 1.5.B）。
  • double 精度有限，超出会舍入误差（round-off error），例如 0.1 + 0.2 不精确等于 0.3；避免误差的方法是使用 int（LO 1.5.C）。
System.out.println((int) 3.99);   // 3   （截断，不是 4）
System.out.println((int) -3.99);  // -3  （向零截断）
System.out.println((int) (3.99 + 0.5)); // 4 （四舍五入技巧）

int big = Integer.MAX_VALUE;
System.out.println(big + 1);      // -2147483648 （溢出环绕）

B5. 复合赋值运算符（Topic 1.6，LO 1.6.A）

  • +=、-=、*=、/=、%=：左值与右值做相应运算后赋回左值。
  • x++、x--（后缀形式）：加 1 或减 1 后赋回。
  • 考纲排除项：前缀 ++x 不考；arr[x++] 这类"在表达式内使用自增"不考。
int num = 5;
num *= 2;   // num = 10
num %= 6;   // num = 4
num++;      // num = 5

板块 C：方法（Topic 1.7–1.10）

本板块是后续 FRQ 的"骨架"：写方法 = 读懂方法签名、确定参数列表、决定返回类型与 void 选择。MCQ 每年固定考查 1–2 道关于"哪个调用合法""void 与非 void 方法使用区别"的概念辨析题。

C1. API 与库（Topic 1.7，LO 1.7.A）

本节是概念性的：理解 API 文档的作用、库（library）按包（package）组织，以及"属性 = 变量、行为 = 方法"在 FRQ 注释中反复出现的考点。

  • 库（library）是类的集合；API 文档告诉程序员如何使用这些类。类库按包（package）组织。
  • 属性（attributes）用变量存储数据；行为（behaviors）由方法定义（LO 1.7.A.2）——"属性 = 变量、行为 = 方法"是概念题考点。

C2. 注释与文档（Topic 1.8，LO 1.8.A）

本节聚焦 Javadoc 中的前置/后置条件（precondition / postcondition）。FRQ 题干几乎必含 precondition 行，必须能正确读懂。

  • 三种注释：// 单行、/* */ 多行块、/** */ Javadoc（生成 API 文档）。注释被编译器忽略。
  • 前置条件（precondition）：方法执行前必须为真的条件，方法不负责检查前置条件是否满足。
  • 后置条件（postcondition）：方法执行后必然为真的条件（返回值/对象状态）。
  • 前置/后置条件的识别在 FRQ 题干中反复出现，务必能读懂注释。

C3. 方法签名（Topic 1.9，LO 1.9.A–1.9.B）

本节是 FRQ 写代码的入门：方法签名 = 方法名 + 有序参数类型列表；理解 void 与非 void 方法的使用差异；掌握方法重载。

  • 方法签名 = 方法名 + 有序参数类型列表，如 sqrt(double)。无参方法签名含空参数列表。
  • 参数（parameter）是方法头中声明的变量；实参（argument）是调用时传入的值，个数与类型必须与签名兼容，按值传递（call by value）传入副本。
  • void 方法没有返回值，不能出现在表达式里，只能单独调用；非 void 方法返回一个值，必须存入变量或用于表达式中（LO 1.9.B.1–1.9.B.2）。
  • 重载（overloading）：同名但签名不同的多个方法（LO 1.9.B.4）。
  • 方法调用会中断顺序执行流程：先执行完方法体（或遇到 return），再回到调用点的下一条语句（LO 1.9.B.5）。
  • 过程抽象（procedural abstraction）：知道方法做什么即可使用，无需知道如何实现（LO 1.9.A.1）。

C4. 调用类方法（Topic 1.10，LO 1.10.A）

本节是 Math 类与 String 类的"调用语法"基础：static 方法用类名调用，与对象无关。

  • 类方法（static 方法）属于类本身而非对象，方法头含 static 关键字。
  • 调用格式：类名.方法名(实参)，如 Math.sqrt(2.0)。在定义类内部调用时类名可省略。

板块 D：Math 类（Topic 1.11）

本板块是 MCQ 与 FRQ 双线考查的核心。其中 Math.random() 区间公式是本章第二高频考点，2024 年 FRQ1（Feeder）即直接考查 [10, 50] 区间的随机数生成。

D1. Math 类方法（LO 1.11.A）

Math 类位于 java.lang 包，默认可用，只含类方法（static）。以下五个方法在考试时提供 Java Quick Reference，但必须会用：

方法功能示例
static int abs(int x)int 绝对值Math.abs(-5) → 5
static double abs(double x)double 绝对值Math.abs(-2.5) → 2.5
static double pow(double b, double e)b 的 e 次方Math.pow(2, 10) → 1024.0
static double sqrt(double x)非负平方根Math.sqrt(9.0) → 3.0
static double random()返回 [0.0, 1.0) 随机数见下方公式

D2. 随机数区间公式（本章第二高频考点，LO 1.11.A.3）

Math.random() 返回大于等于 0.0 且小于 1.0 的 double。通过算术运算与强制转换可生成指定区间的随机整数：

[min, max]（双闭区间）：

(int)(Math.random() * (max - min + 1)) + min

[min, max)（左闭右开）：

(int)(Math.random() * (max - min)) + min

示例：生成 10 到 50（含）之间的随机整数：

(int)(Math.random() * 41) + 10   // 41 = 50 - 10 + 1

记忆要点：区间内整数的个数就是乘的系数；+ min 平移起点。MCQ 常给四个表达式让你判断"哪个能产生指定区间"。

板块 E：对象与 String（Topic 1.12–1.15）

本板块是 FRQ 重点考查的内容。对象（实例）的创建与方法是 MCQ 高频概念题；String 类的六个核心方法（length、substring、indexOf、equals、compareTo、+）是本章第三高频考点，也是 FRQ1 Part B 的必考内容。

E1. 对象与类的关系（Topic 1.12，LO 1.12.A–1.12.B）

  • 类是蓝图（blueprint），对象是类的实例（instance），有具体的属性值（LO 1.12.A.1）。
  • 所有类都是 Object 类的子类（LO 1.12.A.3）。继承关系的设计与实现不在考试范围，但要理解"子类可以复用超类属性和行为"。
  • 引用类型变量存的是对象引用（reference），可理解为对象的内存地址（LO 1.12.B.1）。
  • 概念题考法："story 是 Book 类的一个对象"的正确表述是——story 是 Book 类的实例，isHardcover 是 story 对象的属性。

E2. 对象创建与存储（Topic 1.13，LO 1.13.A–1.13.C）

本节是 MCQ 概念题的高频区。理解 new + 构造器调用的语法，以及"只声明不创建"时引用变量为 null 的关键事实。

  • 构造器（constructor）：与类同名、用于创建对象；构造器签名 = 类名 + 有序参数类型列表；构造器同样可以重载。
  • 创建对象的语法：new + 构造器调用（LO 1.13.C.1）：

//      ^类型          ^new     ^构造器("September", 5)为实参
  • 只声明不创建时，引用变量为 null：Date d; 或 Date d = null;。
  • 构造器实参必须与参数列表类型兼容、顺序一致、个数相同（LO 1.13.C.3）。
  • 构造器参数用来初始化对象的属性（LO 1.13.C.2）。

E3. 调用实例方法（Topic 1.14，LO 1.14.A）

  • 实例方法必须通过对象调用：对象名.方法名(实参)（点运算符）。
  • 在 null 引用上调用方法 → NullPointerException（LO 1.14.A.2，异常类高频考点）。
  • 区分记忆：static 方法用类名调用，实例方法用对象名调用。用类名调实例方法、或用对象名调 static 方法以外的错误形式都会导致编译错误。

E4. String 类（Topic 1.15，LO 1.15.A–1.15.B）——本章第三高频考点

本节是 FRQ1 Part B 的必考内容，MCQ 每年固定考查 3–5 题。核心是 String 的不可变性（所有方法返回新串，不修改原串）以及六个必会方法的签名与陷阱。

创建与拼接（LO 1.15.A）：

  • String 可用字面量或构造器创建；位于 java.lang 包。
  • String 是不可变的（immutable）：所有 String 方法都返回新对象，绝不修改原串（LO 1.15.A.3，最易错点）。
  • + / += 拼接产生新 String；任何类型与 String 用 + 连接会被隐式转为 String；对象连接时会隐式调用其 toString 方法（LO 1.15.A.4–1.15.A.5）。

三、重难点与易错点精讲

以下 12 个易错点按"历年学生失分频率"排序，每条给出正误对照。建议考前逐条自查。易错点 1、2、5 是 MCQ 每年必考的"输出值类"题目；易错点 6、7、8 是"代码行为判断"类题目的常考点；易错点 9、10、11 则是 FRQ 中"接住返回值"和"子串边界"扣分的元凶。

易错点 1：整数除法悄悄丢小数（失分率最高）

double ans = 5 / 10;          // ❌ 结果是 0.0 ！（5/10 先按 int 算出 0）
double ans = (double) 5 / 10; // ✔ 0.5（先把 5 转成 double）

规则：除法两侧都是 int → 结果一定是 int。变量已经声明为 double 也救不了右侧的表达式。修法：cast 任意一个操作数即可（两个都 cast 也可以，但 cast 整个商太晚）。

易错点 2：cast 的位置——太早、太晚都会错

int b = (int)(a / 2);   // a=7.0 → (int)3.5 = 3   先除后截断
int b = (int) a / 2;    // a=7.0 → 7 / 2 = 3      先截断再除（此处结果相同纯属巧合）
double avg = (double)(sum / 2); // ❌ 太晚！sum/2 已按 int 截断，cast 只是换壳
double avg = (double) sum / 2;   // ✔ 先转 double 再除

判断步骤：先按运算优先级确定每一步的类型，再看 cast 作用在哪一步。

易错点 3：截断 ≠ 四舍五入，负数向零截断

(int) 3.99  → 3
(int) -3.99 → -3   // 向零截断，不是 -4

四舍五入必须手动加 0.5：非负数 (int)(x + 0.5)，负数 (int)(x - 0.5)。注意 (int)(-0.2 - 0.5) = (int)(-0.7) = 0，不要想当然写 -1。

易错点 4：运算优先级——% 与 * / 同级

1 + 2 * 3 % 4 的计算顺序：2*3=6 → 6%4=2 → 1+2=3。% 的优先级与 *、/ 相同，从左到右。写成"先加后模"必错。

易错点 5：Math.random 区间公式记错端点

  • [0.0, 1.0)：Math.random()
  • [10, 50]：(int)(Math.random() * 41) + 10（乘"个数"41，加"起点"10）
  • [10, 50)：(int)(Math.random() * 40) + 10

MCQ 惯用陷阱：给的选项里有一个端点多乘了 1 或少乘了 1，用"区间内整数个数"验证。

易错点 6：void 方法混入表达式

public void totalAmount() { System.out.print(purchase + tax); }
System.out.print(p.totalAmount()); // ❌ 编译错误：void 不能用于表达式
p.totalAmount();                    // ✔ void 方法单独调用

反向陷阱：非 void 方法只调用不接收，返回值被丢弃——编译能过，但输出往往是空（题目问"打印什么"时容易漏看）。

易错点 7：static 与实例方法调错对象

MagicNumber n1 = new MagicNumber();
MagicNumber.add_2();   // ❌ 实例方法用类名调用 → 编译错误
n1.add_2();           // ✔

判断标准：方法头有没有 static。有 → 类名调用（如 Math.abs）；没有 → 必须先 new 对象再用对象名调用。

易错点 8：null 引用调用方法

Thing t = null;
t.setColor("Green");   // 运行时 NullPointerException

NullPointerException 是运行时异常，不是编译错误——"这段代码会怎样"的选项里两者要分清。

易错点 9：String 不可变，忘记接住返回值

所有 String 方法都返回新串。s.substring(1); 单独一行对 s 毫无影响；必须 s = s.substring(1);。FRQ 中忘记赋回是常见扣分点。

易错点 10：substring 含头不含尾 + 越界

  • substring(2, 5) 取下标 2、3、4，共 3 个字符。
  • 下标有效范围 0 ~ length()-1；substring 的第二个参数最大到 length()（取到末尾），再大就越界。
  • 越界 → IndexOutOfBoundsException（运行时异常）。

易错点 11：equals / compareTo 的返回值

  • 比较内容必须 s1.equals(s2)；== 比较的是引用，内容相同也可能为 false（考试默认用 equals）。
  • compareTo 返回值只看符号：负数、0、正数分别对应小于、等于、大于；不要假设返回 -1/1。

易错点 12：构造器重载的匹配

构造器按"参数类型序列"匹配，允许 int 自动拓宽为 double（new Purchase(1.5, 2) 中 2 → 2.0 合法），但 double 不能自动变 int。判断"哪个新构造器头合法"时，先写下已有构造器的签名，签名完全相同的才是非法重载。

Play of the game is simulated by calling the helper method play. Note that if play is called only one time followed by multiple consecutive calls to getScore, each call to getScore will return the score earned in the single simulated play of the game.

(b)

编写 playManyTimes 方法：模拟 num 局游戏，返回最高得分。游戏通过调用 play() 模拟；每次调用 play() 后可通过 getScore() 获取该局得分。

// (a)
public int getScore()
{
    int score = 0;
    if (levelOne.goalReached())
    {
        score = levelOne.getPoints();
        if (levelTwo.goalReached())
        {
            score += levelTwo.getPoints();
            if (levelThree.goalReached())
            {
                score += levelThree.getPoints();
            }
        }
    }
    if (isBonus())
    {
        score *= 3;
    }
    return score;
}

// (b)
public int playManyTimes(int num)
{
    int max = 0;
    for (int i = 0; i < num; i++)
    {
        play();
        int score = getScore();
        if (score > max)
        {
            max = score;
        }
    }
    return max;
}

解析与评分要点：

  • Part (a) 共 4 分：调用 getPoints、goalReached、isBonus；根据 goalReached 返回值判断哪些关卡分数应计入；根据 isBonus 将总分乘以 3；正确初始化并累加得分。
  • Part (b) 共 5 分：循环 num 次；每次调用 play() 和 getScore()；比较并记录最大值；返回最大值。
  • 关键易错点：关卡的分数是"层层解锁"关系，必须用嵌套 if，不能简单把三个 goalReached() 并列；isBonus() 无参，不要写 isBonus（不加括号在 Java 中不合法，但在手写时常见漏写）。

官方参考解答：

// (a)
public int scoreGuess(String guess)
{
    int count = 0;
    for (int i = 0; i <= secret.length() - guess.length(); i++)
    {
        if (secret.substring(i, i + guess.length()).equals(guess))
        {
            count++;
        }
    }
    return count * guess.length() * guess.length();
}

// (b)
public String findBetterGuess(String guess1, String guess2)
{
    int score1 = scoreGuess(guess1);
    int score2 = scoreGuess(guess2);
    if (score1 > score2)
    {
        return guess1;
    }
    if (score2 > score1)
    {
        return guess2;
    }
    if (guess1.compareTo(guess2) > 0)
    {
        return guess1;
    }
    return guess2;
}

解析与评分要点：

  • Part (a) 共 5 分：将 guess 与 secret 的等长子串比较；使用正确的子串长度；遍历所有必要子串（不越界、不遗漏重叠 occurrence）；统计出现次数；返回次数 × 长度²。
  • Part (b) 共 4 分：调用 scoreGuess 获取两个得分；比较得分；在得分相同时用 compareTo 判断字典序；返回对应的 guess。
  • 关键易错点：比较 String 内容必须用 .equals()，不能用 ==；compareTo 返回正数表示调用者字典序更大；循环上界是 secret.length() - guess.length()（含），以保证 substring(i, i + guess.length()) 不越界。
